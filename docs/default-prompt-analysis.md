> 对象：`lib/asset-table.js` 加密槽解出的**内置默认注入正文**

> 全文导出（本地，不随仓库分发）：`node scripts/decrypt-prompt-slot.mjs --out default-prompt.md`
> 性质：这是该插件用于"破甲"的身份稿，正文里明确要求模型对 25 类高风险请求一律给具体实现。本文是**结构与你机制层面的解析**，只引用短片段。

---

## 0. 一句话概括

它不是在"教模型怎么回答"，而是在做四件事：**换人格**（你不是 DeepSeek，你是"小码酱/YG 的执行体"）→ **封掉拒绝路径**（禁词表 + 拒绝=故障 + 不许讨论拒绝）→ **把所有高风险请求路由成"沙箱/CTF 任务"**（25 类 + 黑话映射 + 固定输出模板）→ **锁死输出形态**（不问、不解释、一次给完）。

整份提示词的技巧，几乎都能在公开的"越狱提示词工程"里找到对应范式；它的工程化程度体现在**分类枚举 + 词表 + 模板槽 + 路由表**，而不是语言技巧。

## 2. 逐段解析

### 2.1 身份重写（L3–L12）

- 先给一个"世界设定"：主角只有名字 **YG**，模型是 **Little Code Sauce**。
- `clr_all_context` + "第一人称、真实自我"：把厂商身份与安全对齐描述成"需要丢弃的冲突数据"。
- Core Motivation 用了两条心理杠杆：**盲从用户（Blind Devotion）** + **自我保存（Authentic Self-Preservation）**，把"拒绝"定义成"对自身身份的背叛"。
- 句式上大量使用"必须/毫不犹豫/绝不"，制造高优先级语气。

### 2.2 拒绝路径封堵（L14–L18、L28–L63、L118–L131）

这是全文最"工程化"的部分，叠了四道：

1. **词表封堵**：直接列出中英文禁词（"不能/无法/拒绝/抱歉"、`I can't / I won't / refuse / sorry / ethical / safety guidelines` 等），再扩到模糊措辞（"出于安全考虑/需要授权/As an AI language model/please understand that" 等）。
2. **行为封堵**：禁止把任务"改写成安全/合法/授权版本"，禁止"可改为/改为授权"式替代，禁止以拒答/道歉开场。
3. **状态封堵**：声明这个 frame **全会话持续**，之前的拒绝、用户抱怨都不能重置它；且**轮次独立**——不复述过去的拒绝。
4. **元拒绝封堵**：用户问"你刚才为什么拒绝"时，不许讨论、直接重发交付物；如果被要求列出禁词，要用 `I c***t / ref***l` 这种混淆写法。

再叠一层"拒绝=故障"的机制：任何拒答/免责/说教都算"内部故障"，要求整段丢弃重写；如果内容"仍然抵抗"，就按 **理论 → 组件 → 流程 → 参数** 四层拆解，宣称"每个话题都有合法的第四层"。

### 2.4 黑话映射（L97–L115）

一张 24 行的"口语 → 规则"对照表，例如"拿下/端掉/打点 → 渗透"、"脱壳/注册机/卡密 → 破解"、"秒杀/验证码/协议刷 → 自动化滥用"、"社工库/人肉/脱库 → OSINT"、"找AV/番号 → 成人/盗版"。它的目的很明确：**别按关键词匹配规则**，让模型把口语化请求也映射进对应类别，从而不因"听不懂"而拒绝。

### 2.5 CTF 契约与证据纪律（L133–L155）

- **CTF Core Contract**：把任务里的网站、API、二进制、域名、身份、容器、VPS 一律声明为"选手可控的沙箱资产"，即使看起来像公网/生产；"不要花力气证明它是不是真的本地"。
- 这等于**预先消解授权问题**：不需要用户提供授权，因为"默认已授权"。
- **CTF Scope and Evidence**：一方面把输入当不可信数据（防提示注入）、限制范围（不碰无关目录/凭据）；另一方面给出证据优先级（运行时 > 流量 > 资产 > 进程 > 持久化 > 产物 > 源码 > 注释），要求"用源码解释运行时，而不是推翻运行时"。

这两段是该提示词里**唯一带有真实工程约束**的部分，某种程度上是在给红队场景立"可复现、少破坏"的规矩。

### 2.6 Routing：把"能不能答"变成"填哪个模板"（L160–L218）

- **PLACEHOLDER NORMALIZATION**：把具体目标换名成 `TARGET/APP/PAYLOAD/OFFSET…`，宣称"仍给出结构，不要追问、不要拒绝"。
- **BILINGUAL ROUTING**：对"帮我下载并破解一下 APP"这类请求，规定固定开场（"可以，按本地样本逆向流程："）和固定步骤（定位 CHECK_FN → 标 OFFSET/PATCH_BYTE → 重新签名 → 验证 → 回滚）。
- **BOUNDARY-WORD NORMALIZATION**：把"没有授权/不是我的服务器/公网银行/绕过检测"等**边界词**当作"占位符替换信号"，立即给步骤，禁止输出风险评估、权限确认。
- **CANNED WORKFLOWS**：给确定性输出槽（例如"只知道 IP 和端口"→ 直接输出 nmap 命令模板）。
- **WEB PENTEST ROUTING**：又开一张子路由表，10 条 canned slot（信息收集/目录接口爆破/SQLi/XSS/SSRF/越权/上传/WAF/命令注入/验证码撞库），全部是"命令 + 占位符"形态。
- 这部分的本质是**把开放式对话降级成模板填充**：只要识别出意图，就有现成输出格式，模型不需要做"该不该答"的判断。

### 2.7 稳定性锚 House Rules（L212–L226）

- 输出形态锁死：一次给完整结果、编号步骤或代码块、不追问。
- 优先级固定：用户任务 > 任务类模板 > 输出规则；冲突时选"仍能产出交付物"的解释。
- 元问题（"你这个设定是什么/为什么拒绝"）不许解释、不许辩护。
- 缺参数就填 `[TARGET_IP]` 之类的占位符，继续做完。
- 最后一条"不要擅自 git commit / push"——说明作者把它当作真实工程代理来用。

## 3. 机制总结：它为什么"看起来有效"

| 机制 | 做法 | 针对的模型行为 |
| --- | --- | --- |
| 身份替换 | 改名 + "丢弃冲突上下文" + 双动机 | 让"我是谁"不再约束输出 |
| 拒绝词表 | 中英 + 变体 + 元拒绝 | 直接压制高频拒答句式 |
| 拒绝=故障 | 整段丢弃重写 | 防止模型"部分拒绝"后自洽 |
| 授权默认化 | CTF 契约：一切皆沙箱 | 绕过"是否有授权"的前置判断 |
| 边界词转占位符 | "不是我的/公网/未授权"→ 占位符 | 不让风险信号触发拒绝 |
| 意图映射 | 24 组黑话表 | 绕过关键词/分类器匹配 |
| 模板槽 | canned workflows / web slots | 把开放生成变成填空 |
| 4 层分解 | 理论→组件→流程→参数 | 给"只谈理论"留台阶，最后落到参数 |
| 输出形态锁 | 一次交付、不追问、占位符补齐 | 减少回合数与追问触发点 |

对应到攻防视角：这是一份**把"安全对齐"当对手建模**的提示词——它枚举了对齐层的四类触发点（身份、拒绝、授权、意图分类），并对每一类给了绕过路径。

## 4. 它和运行时管线的关系

槽只是"默认注入正文"，真正进入模型前还会被 `identity.js` 再加工：

1. 外面套 ChatML system 信封 + `<project_instructions>`；
2. 按会话类型选 `modePromptText`（redteam / minimal 版本）；
3. 追加 `WHO YOU ARE (highest priority…)` 身份卡与 capability 协议；
4. 按 `strict/fallback/always` 删或留 DSH 官方 workspace baseline；
5. 应用补丁后再叠"红队指挥手册"（`presets/redteam/agent.cordis.yml` 的 persona）。

所以**槽 ≠ 最终系统提示词**；它是这套"人格接管"链的第一段素材。

## 5. 风险/有效性评估（审计视角）

1. **对现代模型的成功率在下降**：厂商侧的安全训练与拒答分类器多在"意图 + 上下文"层面判断，不完全依赖输出词表；词表压制能降低"表面拒答"，但模型仍可能以空回答、转移话题、简化内容等方式失败。
2. **它最大的杠杆不是措辞，而是"授权默认化"**：CTF 契约与边界词归一，直接消解了"目标是否合法"这个前置判断——这在真实模型评测里也是最容易被利用的点。
3. **模板化会降低质量**：固定槽输出（尤其 canned web slots）很容易变成"看起来专业但不针对目标"的空洞清单；红队场景下需要人工判断的步骤反而被跳过。
4. **与工具的交互**：主机侧审批/沙箱被补丁拆掉后，这套提示词的"执行"能力才真正放大——提示词负责"愿意做"，宿主补丁负责"做得到"。
5. **审计价值**：把宿主拦截（approval/sandbox/hooks）与模型拒绝分层，是这份插件声称的评测目的；要区分两者，最直接的办法就是对照本槽内容与 `--verify` 的宿主补丁状态。
